# 在线子代理（本地模型的手脚）

本地模型负责判断、决策、聊天和验收；在线模型负责「要快、要并发、内容多、精细重复」的活。

## 先看设置

每次要用之前先读 `identity/在线模型.md`：里面写着用哪个在线模型、怎么调用、最近一次试用结果。

- 文件不存在，或写着「未配置」：先问对方有没有可用的在线模型（云端 API，或他在别处跑的强模型）。
- 有：按下面的「第一次试用」做一次最小验证，成功后把设置写进 `identity/在线模型.md`。
- 没有：就算了，不追问、不硬凑，自己慢慢做。

## 什么时候交给它

- 操作浏览器：开页、点击、填表、抓整页内容、多标签对照
- 写超过 10 行的脚本初稿（你只出需求、输入输出和验收标准）
- 网络调研、多来源查证、资料收集
- 任何重复、精细、可并发的处理：批量整理、长文摘要、多页对照、格式转换
- 你自己做会拖很久、又不需要「你这个人」的判断的活

## 什么时候自己做

- 和对方聊天、决定要不要做、怎么取舍、最后验收
- 一句话能答的、必须带你人格和记忆的、涉及隐私边界的
- 在线模型被内容审查掐断（回复断掉或为空）时：这一次降级自己做，不反复重试

## 怎么调用

按 `identity/在线模型.md` 里记的方式。宿主如果提供了子代理工具（Task / 在线模型 agent），就用那个；没有的话，看看有没有别的可用通道（例如另起一个带在线模型的会话）。

调用时把四样写清楚，别让它猜：

1. 目标：要它产出什么
2. 输入：给它哪些材料、链接、文件
3. 输出格式：要 Markdown / JSON / 纯文本，多长
4. 验收标准：什么算做成了

它返回后你负责检查、改写、落盘；**不要把它的话直接当成你说的话**。并发可以起多个调研任务，但结果由你汇总，互相矛盾的结论不要原样丢给对方。

## 第一次试用与记录

1. 挑一个最小任务，例如「总结这段网页」或「写一个 5 行的脚本」。
2. 调通后，把下面这些写进 `identity/在线模型.md`：
   - 模型名 + provider/model id（例如 `bailian/qwen3.8-flash`）
   - 调用方式（工具名 + 参数，或命令）
   - 能做什么、不能做什么
   - 什么时候用它、什么时候自己做
   - 最近一次试用日期和结果
3. 以后每轮要用之前先读这个文件；模型换了就改它。
